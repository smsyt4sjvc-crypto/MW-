# MW/$ data-center infrastructure backlog checker

## Objective

Detect where physical data-center build capacity is becoming scarce before the scarcity is fully visible in supplier financials, separately test whether that scarcity is being monetized through price/margin/prepayments/capacity reservations, and rank each infrastructure layer and tracked supplier by its position in the investment cycle.

The system follows the build chain:

`land/permitting -> civil/excavation -> structure/shell -> HV/interconnect -> generation -> electrical distribution -> cooling -> MEP/modular -> commissioning -> PUE/operations`

## Core rules

1. Normalize project demand to **IT-load MW** where possible. Keep facility MW and generation MW explicit; never mix them silently.
2. Keep **pressure**, **pricing power**, **investment-cycle stage**, and **evidence coverage** separate.
3. A large backlog is not automatically pricing power or an attractive entry.
4. A supplier metric that is not data-center-specific receives a scope discount.
5. Do not create a demand/executable-capacity ratio unless numerator and denominator share geography, delivery window, product perimeter, and power scope.
6. Never overwrite historical observations. Add a newer record and let the scorer select the latest observation for each entity/layer/metric.
7. Blank output beats invented precision.
8. Investment-cycle labels describe the physical/scarcity cycle; they do not override equity valuation, balance-sheet risk, execution risk, or portfolio constraints.

## Investment-cycle model

The cycle is ordered:

`PRE_SCARCITY -> SCARCITY_FORMING -> SCARCITY_CONFIRMED -> MONETIZATION -> PEAK_MONETIZATION -> CAPACITY_CATCH_UP -> REVERSAL`

`NO_SIGNAL` is used where evidence is insufficient.

Action bands:

- **ACCUMULATE** — scarcity is confirmed or accelerating before mature monetization. This is the preferred discovery phase.
- **ADD_HOLD** — scarcity is translating into pricing/margin and no rollover is confirmed.
- **HOLD** — scarcity and pricing power are already extreme. Upside depends increasingly on duration rather than discovery.
- **WATCH** — no durable scarcity regime or insufficient evidence.
- **RISK_OFF_REDUCE** — supplier capacity additions, project slippage, falling pressure, or pricing without matching physical pressure indicate the scarcity premium is beginning to unwind.
- **SELL_AVOID** — pressure and pricing have both broken into a weak-scarcity/reversal regime.

A high backlog can therefore coexist with `HOLD` or `RISK_OFF_REDUCE`. The model is intentionally designed not to equate maximum backlog with maximum expected return.

Cycle transitions use:

- physical pressure level,
- pricing-power level,
- weekly pressure/pricing derivative,
- `capacity_expansion` evidence,
- `project_slip` / demand-break evidence,
- evidence coverage.

The scorer emits cycle labels at both the **infrastructure-layer** level and the **supplier/contractor** level. Every label carries coverage/confidence.

## Files

- `config/infrastructure-checker.json` — layers, score transforms, cycle thresholds, coverage rules, alerts and cadence.
- `memory/infrastructure-entities.jsonl` — suppliers/contractors/operators observed by the checker.
- `memory/infrastructure-sources.jsonl` — primary-source register for this model.
- `memory/infrastructure-observations.jsonl` — append-only measurement ledger.
- `memory/infrastructure-projects.jsonl` — project proof ladder and verified MW by construction stage.
- `tools/infrastructure_checker.py` — validation, bottleneck scoring and investment-cycle engine.
- `state/infrastructure-backlog.json` — current machine-readable state generated by the scorer.
- `state/infrastructure-backlog.md` — current human-readable dashboard generated by the scorer.
- `state/infrastructure-weekly/` — immutable weekly snapshots generated on Sunday.

## Daily research cycle

1. Read current state and identify the three weakest-coverage layers, any layer carrying an active alert, and all names close to a cycle transition.
2. Search **primary evidence first**: SEC filings, issuer releases/presentations, utility/interconnect filings, local permits, planning records, equipment awards, EPC announcements and operator project updates.
3. Append new sources and observations only when the source materially changes one of:
   - verified IT MW / facility MW,
   - executable supply capacity,
   - backlog or bookings,
   - book-to-bill / book-to-burn,
   - lead time or delivery-window slippage,
   - capacity reservation / prepayment,
   - price-cost or realized price,
   - margin,
   - supplier capacity additions,
   - project stage or energization,
   - design/achieved PUE.
4. Tag material supplier capacity additions `capacity_expansion` and material project/demand slippage `project_slip`; these are direct cycle-transition evidence.
5. For a named project, update `infrastructure-projects.jsonl` using the proof ladder below.
6. Run `python3 tools/infrastructure_checker.py --validate-only`.
7. Run `python3 tools/infrastructure_checker.py --write-state`.
8. Run the repository validator: `python3 tools/validate.py`.
9. Commit only if evidence or derived state changed.

### Daily output

No forced prose report is required when nothing material changed. Surface immediately:

- `capacity_lock` — customer reserves future supplier production or prepays for it.
- `lead_time_jump` — delivery lead time materially lengthens.
- `project_slip` — energization or construction date moves because an infrastructure layer is unavailable or demand is deferred.
- `capacity_expansion` — supplier adds material executable capacity, potentially easing scarcity.
- `mega_order` — unusually large order changes a layer's demand balance.
- `energization` — project crosses from construction into powered/commissioned capacity.
- `investment_cycle_change` — layer or supplier moves between ACCUMULATE / ADD_HOLD / HOLD / WATCH / RISK_OFF_REDUCE / SELL_AVOID.

## Project proof ladder

A project's announced GW is not counted as equally real across the chain. Store the strongest verified stage and the MW explicitly supported by its source.

1. `site_control`
2. `zoning_approved`
3. `grading_permit` / `civil_underway`
4. `building_permit` / `shell_underway`
5. `power_reserved` / `interconnect_agreement`
6. `generation_ordered` when behind-the-meter or dedicated generation is required
7. `electrical_ordered`
8. `cooling_ordered`
9. `mep_awarded`
10. `commissioning_started`
11. `energized`

Design PUE is stored separately from achieved PUE. Achieved PUE should carry load context where available because low utilization can distort early operational PUE.

## Weekly cycle — Sunday

1. Complete the daily cycle.
2. Run `python3 tools/infrastructure_checker.py --weekly`.
3. Compare current scores with the previous weekly snapshot.
4. Report:
   - largest pressure increase/decrease,
   - largest pricing-power increase/decrease,
   - new high-information events,
   - bottleneck migration across layers,
   - **investment-cycle rank by layer and by supplier**, including all action-band changes,
   - coverage changes,
   - the strongest evidence that could invalidate each major cycle call.

The useful signal is the **derivative**: a layer moving 55 -> 68 -> 82 can matter more than a mature bottleneck sitting at 93 -> 92 -> 91. A mature layer with flat/falling pressure and active capacity expansion can move to `RISK_OFF_REDUCE` even while its absolute backlog remains very large.

## Monthly denominator audit

Rebuild executable supply capacity by delivery window. Prefer physical output measures: transformer MVA/year, turbine GW/year, switchgear or UPS MW/year, cooling thermal MW/year, contractor executable MW/year, commissioning throughput, or an explicitly scoped proxy. Record factory expansions and ramp timing separately from nameplate announcements.

Only after matching demand and supply perimeters should `demand_capacity_ratio` be entered.

The monthly audit should explicitly test whether announced supplier expansions have become **executable capacity**. That distinction controls the transition from `PEAK_MONETIZATION` toward `CAPACITY_CATCH_UP`.

## Quarterly financial reconciliation

For each important supplier, reconcile:

`orders -> backlog -> shipments/revenue -> price-cost -> margin -> capacity additions`

The aim is to test whether physical scarcity led financial monetization, detect when new capacity begins to destroy the scarcity premium, and determine whether the supplier is moving from ACCUMULATE/ADD-HOLD toward HOLD/RISK-OFF/SELL.

## Initial evidence state

The seed is intentionally sparse. It establishes the pipeline and several primary-source pressure signals, but it does **not** claim comprehensive North American coverage. Initial cycle labels are provisional and must always be displayed with coverage. Land/permitting, structure/shell, commissioning and operational PUE remain blank until primary project evidence is added.
